# ADR-001: Go for the wallet service

Status: accepted — Date: 2026-11-18

## Context

Tourist is a learning project: no deadline, no users, no other contributors. I've worked on a digital wallet before, but not at the scale wallet-core targets, 100x that system's biggest customer ([.design/wallet-core.md](../../.design/wallet-core.md)). I know C# well and want to learn a second backend language that performs well.

## Decision

The wallet service is written in Go.

## Alternatives considered

**C#.** Faster to ship, and it performs about as well for this kind of service. Rejected: the goal is learning, and with no deadline, shipping speed isn't a constraint.

## Consequences

- Delivery is slower than in C#.
- Two unknowns at once, a new language and a new scale. The load spike (#3) measured PostgreSQL alone, so it's the baseline that separates Go problems from design problems.
- No built-in decimal: money is integer minor units (`bigint`), single currency for now.

## Revisit when

Tourist stops being a learning project (real users, a delivery date, other contributors).
